## 1. 怎样证明功能正常运行

不仅检查公式，也要检查同一笔记录如何被提交、审批、写入、刷新、退款和作废。资金类功能至少需要三层验证：

| 层级 | 验证内容 | 工具/环境建议 | 不可用什么替代 |
|---|---|---|---|
| 领域单元/性质测试 | 十进制计算、重放顺序、成本、收益率、比例、尾差、状态转换 | 沿用Vitest；预期值来自独立十进制算例 | 不能只拿同一被测函数算预期值 |
| 数据库集成/并发测试 | RPC、RLS、锁、幂等、事务回滚、跨账本校验、迁移 | 独立本地Supabase/PostgreSQL测试库，两个真实用户会话 | 不能用mock数据库证明事务和权限正确 |
| 双人端到端/视觉验收 | 两人独立会话提交和审批，页面同步、错误提示、组合原子结果、旧设计保留 | 浏览器自动化建议Playwright，外加关键页面视觉核对 | 不能只检查页面能打开或返回200 |

辅助检查：TypeScript、Lint、构建、全新库安装、旧库升级、超过服务端分页上限的汇总、网络失败后的重试。工具新增仅用于测试，不更换应用框架或视觉体系。

## 2. 固定测试数据和可复现条件

- 成员A、B同属账本H；成员C属另一账本J；另设未登录和失活成员。
- H包含银行和券商各一个共同账户；不创建成员个人资产账户。
- 汇率版本FX1：1 USD=7.2 CNY=7.8 HKD；FX2：1 USD=7.5 CNY=7.8 HKD。均为合成测试值，不是真实报价。
- 分类保留既有项，增加玩乐/日用/购物；事项“香港旅行”；新增自定义“运动娱乐”。
- 标的X为USD、Y为CNY、Z为HKD，数量/价格/估值日期固定；所有金额以十进制定义。
- 固定发生时刻、账本时区、稳定事件序号及批准时刻；暂停真实时间依赖。测试不得因为当地跨午夜而随机失败。
- 每个案例从独立已知数据开始，除明确的多步骤测试外不依赖前一案例残留；测试数据不进入用户真实账本。
- 1000条限制场景至少生成1500条，另用10,000条混合事件检查全量汇总；记录实际耗时和环境，不用未经测量的固定性能承诺。

## 3. 重要数值场景：输入、操作与预期

### T-01 双向禁止自动调钱（AC-42/43）

分开执行两组：

1. 银行USD600、券商USD20，使用“现有券商现金”买入实际扣款200。批准后银行600、券商−180、投资成本200；没有划转记录。
2. 银行USD20、券商USD600，银行共同消费100。批准后银行−80、券商600；没有券商转银行记录。

验证领域结果、RPC新增明细和UI。不能只看两个账户合计，因为错误地挪钱后合计也可能一样。

### T-02 显式银行转入并买入（AC-44—48）

初始银行600、券商20，买入B=200；分别测试T=300、200、100：

| 手工转入T | 批准后银行 | 批准后券商 | 共同现金 | 投资成本增加 |
|---:|---:|---:|---:|---:|
| 300 | 300 | 120 | 420 | 200 |
| 200 | 400 | 20 | 420 | 200 |
| 100 | 500 | −80 | 420 | 200 |

审批前均无正式变化。必须有转入、转出和投资扣款的关联事实，但共同现金只减少B一次。T不得在审批时被改为当前券商缺口。另一笔事件在审批前改变券商余额，批准只在新余额上加固定的T−B。

对事务故障分别注入：银行扣款后、券商入账后、投资写入后；每种故障都应整体回滚。相同请求重试只产生一组结果。组合若被后续卖出依赖，作废必须先验证整个持仓链路。

### T-03 跨币种银行资金买入（AC-46）

初始银行CNY7,200、券商USD10。用户指定转出CNY720、券商实际到账USD100，买入USD80；批准后银行CNY6,480、券商USD30、投资成本USD80。

FX1下批准前现金USD1,010，批准后现金USD930；若投资按成本暂估USD80，共有资产仍USD1,010，不计贡献或消费。若实际到账不是100，按实际两侧金额处理并显示净额折算差额，不能后台改到账金额来满足参考汇率。

补充实际到账USD95的分支：银行仍CNY6,480，券商变USD25，现金USD925、成本暂估投资80，共有资产USD1,005，比原先少USD5。该差额来自实际换汇净额，不是买入重复扣款，也不是投资已实现亏损。

### T-04 含费实际金额（AC-49）

100份，参考交易报价10，实际买入总扣款1,002；报价只备注，不作为额外扣款。买入成本1,002，含费单位成本10.02。卖40份实际净到账598：

```text
结转成本 = 1,002 × 40 / 100 = 400.80
剩余数量 = 60
剩余成本 = 601.20
已实现收益 = 598 − 400.80 = 197.20
买卖现金净变化 = −1,002 + 598 = −404
```

不得再扣一次手续费，不得因为1,002不等于100×参考10而拒绝有效记录。若人工确认当前单位市值10，持仓市值600、浮盈−1.20、涨跌幅约−0.20%。

### T-05 加仓、部分卖出与涨跌幅（AC-50/51/55）

买100份扣款1,000，确认总市值1,200，涨20%。以同估值卖40份时剩余成本600、市值720，仍涨20%，不能显示−28%。

独立重置：买100份扣款1,000、估值1,200，再买50份扣款600：数量150、成本1,600、旧价格估算市值1,800、浮盈200、涨12.50%。卖60份净到账840后：数量90、成本960、已实现收益200、旧价格市值1,080、浮盈120、仍涨12.50%。

再收到净分红20：现金+20，累计分红+20，持仓涨跌幅仍12.50%；累计总收益额从320增到340。验证卡片不会把分红加入持仓涨跌幅分子。

### T-06 全卖、尾差、清仓后重新买（AC-52/53）

3份总成本100，按1份分三次卖出，净到账分别40/40/40。采用到分的移动平均，结转成本依次33.33、33.34、33.33；累计已实现收益20，最后持仓0、成本0。

再买10份总扣款200，新持仓数量10、成本200，旧已实现20保留；旧批次估值不作为新批现价，市值先成本暂估200、涨跌幅“待估值”。不能将新买入视为把旧成本或亏损复活。

### T-07 涨跌幅边界（AC-54/60）

| 条件 | 预期 |
|---|---|
| C100、人工确认M0、Q>0 | −100% |
| C0、Q0 | 已清仓，涨跌幅“—” |
| Q>0、合法迁移成本0、M50 | 无成本基数，涨跌幅“—”，市值50仍可展示 |
| C100、仅成本暂估M100 | 待估值，不显示实际涨跌0% |
| 人工M120、C100但估值过期 | +20%，带估值日期/过期提示 |
| 更新M150但待审批 | 正式市值仍120，不能提前变+50% |

确认没有NaN、Infinity、除零错误或用缺失价格当真实0市值。

总市值模式舍入补充：3份确认总市值1，显示单位价0.33333333；后来按同一估值依据计算2,000,000份的暂估市值，应使用`round(2,000,000×1/3)=666,666.67`，不能用显示单价相乘得到666,666.66。显示舍入值不得成为核算来源。实际达到该数量需有效买入记录，测试可分别构造领域数量输入与完整交易序列。

另外测试零价处置：10份成本100，全部卖出净到账0，数量/成本归0、已实现收益−100、现金不变。此类合法零到账卖出不能被通用“金额必须大于0”规则误拦，也不能被当成没有发生的事件。

### T-08 多币种投资配置（AC-56/57/61）

标的A市值USD600、B市值CNY2,880；FX1下分别折算600/400，配置60%/40%。即使银行现金USD10,000、券商闲钱USD500、欠成员USD300，投资配置仍60%/40%，分母仍1,000。

独立重置A市值USD100、B市值CNY720，FX1配置50%/50%；更新FX2后为100/96，占比51.020408…%/48.979591…%，显示51.02%/48.98%。若本币成本和市值没变，各标的本币涨跌幅不随该汇率变化。

### T-09 配置尾差与缺失（AC-58/59/62）

三个标的相同报告币种市值，真实比例各1/3；标签按稳定ID次序分配尾差为33.34%、33.33%、33.33%，合计100.00%，原始比例不改。同类别归组后按原金额再算，不用已舍入标签相加代替。

全部市值0：空状态，无除零。某非零持仓缺必要汇率：整体配置标待完善，不把它当0或将其余已知项重新变成100%。成本暂估存在时可以展示含暂估配置，但全图与对应项都标注。负银行现金不进入投资占比分母；总体资产图不得产生负面积环形扇区。

### T-10 跨币种报销、预留与汇率变化（AC-16/17/18/19/67/68）

A代付CNY720旅行与HKD780餐饮。FX1下，一次USD150打款核销CNY360与HKD780。批准前原单预留360/780，现金不变；批准后现金−150、原币余额360/0、消费不再增加。

FX2下剩CNY360折合USD48，原债权、已付USD150、原消费锁定金额不变。分配用原币额度控制，不能以新的USD折算额反推修改历史核销。

另测三笔CNY1的核销，FX1下付款本金四舍五入USD0.42，三个付款分配USD0.14，原币各核销1。三笔CNY0.01合计折算仍小于USD0.005，付款舍入为0，必须拒绝零付款核销并要求合并/调整，不能把债权静默清零。

再测同批含一笔USD1和一笔CNY0.01：整体付款虽为USD1.00，CNY0.01那条按尾差分配后仍为0，必须拒绝该组合，提示增加该原单合法核销额或改原币支付；不能把小额原单无偿标记结清。

### T-11 退款的两个方向与成员返还（AC-25/26/63/64）

A代付300、已报销100，商家退250给A：消费净额50，可报销额50，已付100，因此欠款0、A应返共同款50；共同现金在商家退款时不变。A返还50获批后现金+50，应返款0，贡献不变。

独立重置：A代付300尚未报销，商家直接退共同账户100：共同现金+100，消费净额200，但仍欠A300，因为A的个人垫付没有被偿还。不能同时把欠款减为200。

若原代付100已有80预留，再申请退50给个人，必须在批准退款前处理冲突预留；不能让有效预留80大于可报销50。

### T-12 分类与来源不重计（AC-39/40/41/31）

共同银行支付“玩乐”100，A代付“日用”50，B代付“购物”80；随后共同账户报销A50/B80。消费合计230，类别分别100/50/80，报销不再使消费变460。

## 4. 操作、故障、权限与迁移场景

数值单测无法覆盖以下情形，必须使用相应环境执行。具体AC编号见主索引。

| 场景 | 操作 | 必须观察的结果 | 层级 |
|---|---|---|---|
| 重复提交 | 同一草稿双击，网络丢响应再重试 | 一份提案/一次入账，稳定返回同一ID | DB+E2E |
| 并发批准 | A/B会话同时重复请求同一有效提案 | 非提交者有效批准一次，余额/核销不重复 | DB |
| 并发超额预留 | 同一100余额同时两笔申请80 | 一笔成功，另一笔显示可用20 | DB |
| 并发合法核销 | 同一100余额同时两笔申请40和60 | 都可依规则成功，总核销100，不能丢失更新 | DB |
| 撤回后迟到批准 | 客户端审批页旧状态，提交者已经撤回 | 明确状态冲突，不写现金/持仓 | DB+E2E |
| 逾期 | 固定时钟前进72小时 | 逾期标签、仍需人工审批、预留不凭空释放 | 单元+E2E |
| 部分写入故障 | 现金/持仓/分配写入之间人为抛错 | 整体回滚，重试后只一笔 | DB |
| 读请求失败 | 查询超时或权限失败 | 错误/重试界面，不以空数组显示余额0 | E2E |
| 实时更新时序 | 一人批准，另一人同时看现金与投资 | 同一账本版本，重新连接后收敛为一致状态 | E2E |
| 乱序/同日/补录 | 多笔同日事件改变展示顺序和历史输入 | 数值按稳定业务顺序；估值份额失效显式阻止 | 单元+DB |
| 作废依赖 | 作废已被卖出消耗的买入或有核销的代付 | 列出依赖，不能只撤部分金额 | DB+E2E |
| 真实退款 vs 作废 | 执行两条不同流程 | 退款保留原消费事实；作废保留审计并重放，不混为一谈 | DB+E2E |
| 越权引用 | C使用H账本或标的/原单ID，调用旧RPC | 所有读写被拒，不泄漏其它账本数值 | DB |
| 邀请并发 | 不同邀请同时接受 | 活跃成员最多2人，登录后返回正确邀请路径 | DB+E2E |
| 归档竞态 | 一请求批准交易，一请求批准归档 | 锁与状态一致，归档后不新写普通事件 | DB |
| 归档恢复 | 直接旧RPC写估值/汇率、单方恢复 | 普通写入拒绝，仅正确双人恢复后解锁 | DB+E2E |
| 超分页 | 1500/10,000条多币种/投资/代付事件 | 服务端全量聚合正确，列表页大小不影响总额 | DB |
| 时间边界 | 账本午夜、UTC换日、同秒多个事件 | 列表/统计归同一业务日，顺序稳定 | 单元+E2E |
| 极端数值 | 小额、最大允许金额/数量、NaN、Infinity、负输入、超过精度 | 合法值精确，非法值在API与DB一致拒绝，不溢出 | 单元+DB |
| 旧数据不明 | 历史收款人或核销关系缺失 | 待核对，不能自动猜测导致真实欠款改变 | 迁移 |
| 迁移重跑/恢复 | 切换日期期初确认后故障恢复再执行 | 总资产/现金不双计，幂等，可追溯旧数据 | 迁移 |
| 界面兼容 | 桌面与移动端完成全流程 | 保留原色彩/四页主结构，新入口清晰，金额不被遮挡 | E2E+视觉 |

## 5. 始终成立的核算性质

除固定算例外，用受约束随机事件序列验证以下性质；序列先保证业务合法，不通过“遇到非法事件就忽略”来让测试通过。

1. 同币种转账的两条现金明细之和为0，贡献/消费/投资收益均不变。
2. 同币种银行转入并买入组合的共同现金变化为−B，与转入金额T无关；跨币种则为`−convert(T_c)+convert(T_d)−convert(B_d)`，两账户实际金额都不能被系统改写。
3. 没有显式划转的事件不能写另一账户现金明细；负余额不例外。
4. 买入后累计成本增加实际扣款一次；部分卖出结转比例成本；全部卖出累计结转成本恰好清零。
5. 投资回放不受UI排序/分页影响；合法重放数量与成本非负，不能略过坏事件。
6. 当前消费=有效账户消费+有效代付−有效退款；报销/投资/存入不增加它。
7. 新增付款时，新增核销/预留不能超过当时未清债权；任一当前状态均须`R_i<=L_i`。后续退款可能合法导致历史`S_i>A_i`，超出部分必须可由应返款及已返还解释，不能一概作为超额报销错误。预留转核销时总占用不重复增加。
8. Σ付款币分配=批次付款本金；原币核销额度独立保存，不随汇率切换改变。
9. 实际市值和成本完整且C>0时，持仓涨跌幅=(M−C)/C；分红单独变化不会改这个公式。零成本/清仓/未估值按明确状态展示，不执行除法。
10. 完整且正总市值时，各标的原始配置占比之和为1；每一类别的金额等于其明细市值之和。
11. 当前汇率更新不修改原币现金/数量/原币成本/历史核销；本币涨跌幅不变。
12. 无依赖的事件作废后，正式余额等于从未计入该事件时的核算结果，但原审计事实仍存在。
13. 以同一版本、同一汇率计算：共有净额=银行现金+券商现金+投资市值−未报销垫款+成员应返共同款。
14. 同一幂等请求执行任意次数，财务效果与执行一次相同。
15. 迁移模式中“确认期初＋切换后事件”与核对的完整历史余额一致，不能同时把旧历史加第二次。

80个场景是当前覆盖范围，不是测试数量上限。一个场景可拆为多条自动化测试；类似参数可以表格驱动，避免复制代码。发现新错误后，先保留复现数据和针对性回归，再修复；不以盲目堆测试数量替代覆盖交易链路。

## 7. 结果记录模板

每次验收记录：用例ID、PRD版本、代码提交、数据库迁移版本、环境/时区、测试数据、预期、实际、结果（未执行/通过/失败/不适用）、日志或截图、关联缺陷、修复后复测结果。

必须区分四件事：公式在文档里算对了、领域函数算对了、数据库原子且有权限地写对了、两人从页面操作也得到同样结果。本轮仅完成第一项的核心算例校验；后续开发按阶段补齐其余证据。
